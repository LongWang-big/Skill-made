# 智能日报生成器 proposal.md

## 1. 背景与目标
### 1.1 背景
（简述五个痛点：费时、散落、易漏、协作丢失、难汇总）
### 1.2 目标
（一句话：自动采集三源数据，生成团队日报并推送，实现零手工）

## 2. 功能范围
### 2.1 做什么（本期）
- 采集：GitHub提交、飞书任务、飞书群消息
- 生成：三段式编排、个人与团队汇总
- 推送：SMTP邮件、飞书机器人
### 2.2 不做什么（本期明确排除）
- 不做智能摘要与AI总结
- 不做Web界面与移动端
- 不做考勤数据采集（v1.1再议）
- 不做多团队多租户支持

## 3. 隐含需求
- 跨系统身份映射表
- 单源失败降级与显式标注
- 零记录与获取失败的区分
- 非工作日自动跳过
- 敏感信息脱敏过滤

## 4. 技术约束
- 开发语言：Python 3.11+
- 部署运行：Cron定时任务（无常驻服务）
- 数据存储：本地SQLite
- 外部依赖：GitHub API、飞书API、SMTP

## 5. 成功标准（可度量）
### 5.1 功能验收
- [ ] 准确获取指定仓库过去24h的Commit记录
- [ ] 准确获取飞书当日状态变更的任务
- [ ] 日报包含“代码/任务/协作”三个核心板块
- [ ] 成功发送HTML邮件至Leader
- [ ] 成功通过机器人推送Markdown至群组
### 5.2 性能与边界验收
- [ ] 单次生成耗时（5人团队）< 60s
- [ ] 单一数据源超时，不阻断其他源采集
- [ ] 数据源失败时，日报显式标注“数据获取失败”
- [ ] 无记录时，日报显示“今日无记录”

## 6. 术语定义
- 采集窗口：默认为当日00:00至任务执行时刻
- 成员：已完成GitHub与飞书账号映射绑定的团队成员
